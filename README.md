
# STEMly — Interactive STEM Simulation Generator

> Type any STEM concept and explore it through a live, interactive simulation.

STEMly is an AI-powered educational web application that transforms STEM concepts into interactive visual simulations. Instead of relying only on static diagrams or lengthy explanations, users can explore concepts by adjusting sliders, toggling parameters, and observing how the visualization changes in real time.

Enter a topic such as **wave interference**, **ionization energy**, or **Bayes' theorem**, and STEMly generates a self-contained simulation designed to make the concept easier to understand through experimentation.

## Overview

Learning STEM subjects can be difficult when abstract concepts are presented only through equations, text, or static diagrams. Many scientific and mathematical ideas become easier to understand when learners can experiment with variables and immediately observe the results.

STEMly aims to make that kind of exploration accessible through an AI-generated simulation experience.

The application accepts a topic from the user and sends it to a backend API. The server uses Anthropic's Claude model to generate a complete HTML simulation containing its own styles, controls, and visualization logic.

The generated simulation is then rendered inside a sandboxed iframe, keeping its execution separate from the main application. If the simulation encounters a runtime error, STEMly can send the error and previous code to a repair endpoint and attempt to generate a corrected version.

### Example Topics

- Wave interference
- Simple harmonic motion
- Newton's laws of motion
- Projectile motion
- Ionization energy
- Chemical bonding
- Bayes' theorem
- Probability distributions
- Derivatives and gradients
- Electric fields
- Planetary motion
- Machine learning concepts

The simulation's controls and visualizations depend on the topic and the code generated by the AI model.

## Key Features

### 1. AI-Generated Simulations

Users can enter a STEM concept in natural language. STEMly sends the topic to the backend, where Claude generates a standalone HTML document for the requested simulation.

The generated document can contain:

- HTML structure
- Inline CSS
- JavaScript logic
- Interactive input controls
- Canvas or SVG visualizations
- Explanatory labels and values

### 2. Interactive Controls

Generated simulations are designed to include controls such as:

- Range sliders
- Toggle switches
- Adjustable parameters
- Live numerical values

These controls allow users to change simulation parameters and observe the resulting changes.

For example, a wave simulation may allow users to adjust amplitude, frequency, or phase difference and observe how the resulting wave changes.

The exact controls depend on the simulation generated for each topic.

### 3. Live Visualizations

STEMly asks the AI model to create visualizations using browser-based technologies such as Canvas or SVG.

Depending on the generated simulation, visualizations may include:

- Waveforms
- Motion paths
- Graphs
- Particle diagrams
- Geometric illustrations
- Scientific models

The goal is to make cause and effect visible through direct interaction.

### 4. Sandboxed Simulation Rendering

Generated HTML is rendered inside an iframe using `srcDoc` and a sandbox configuration.

This separates the generated simulation from the main application and limits its browser capabilities.

The iframe uses:

```html
<iframe sandbox="allow-scripts" srcDoc="..."></iframe>
```

The sandbox allows scripts to run inside the frame while withholding other iframe permissions unless explicitly added.

### 5. Automatic Error Detection

STEMly injects a small JavaScript shim into the generated document before it runs.

The shim installs listeners for:

- `window.onerror`
- `unhandledrejection`

When a supported runtime error is detected, the shim sends error information to the parent application using `postMessage`.

### 6. Automatic Simulation Repair

If a generated simulation crashes, STEMly can attempt to repair it automatically.

The repair process sends the following information to the healing API:

- The original topic
- The latest generated HTML
- The reported error

Claude then attempts to return a corrected simulation document.

The iframe is remounted with the repaired code. STEMly allows up to three healing attempts before showing an error state.

### 7. Loading, Error, and Healing States

The interface supports different stages of the simulation workflow:

- Idle state
- Loading state
- Ready state
- Healing state
- Error state

This helps communicate what is happening while a simulation is being generated or repaired.

### 8. STEMly Design System

The application uses a shared visual style across the main interface and generated simulations.

The design system includes:

- Shared color palette
- Typography choices
- CSS design tokens
- Consistent visual styling

The generation prompt uses the same palette and theme definitions so that generated simulations can visually match the STEMly interface.

## How It Works

STEMly follows a topic-to-simulation workflow.

### Step 1 — Enter a Topic

The user enters a STEM concept into the search interface.

Example:

```text
Wave interference
```

The `SearchInterface` component sends the topic to the generation API.

### Step 2 — Generate the Simulation

The frontend sends a request to:

```text
/api/generate
```

The API route uses the Anthropic Messages API to ask Claude to generate a self-contained HTML document.

The generation instructions are defined in:

```text
lib/prompts.ts
```

The prompt asks for an interactive simulation that includes its own HTML, CSS, JavaScript, and controls.

### Step 3 — Receive the HTML

The backend processes the model response and extracts the generated HTML document.

The response is returned to the frontend, where the simulation can be displayed.

### Step 4 — Render in the Iframe

The `SimulationFrame` component receives the generated HTML.

Before execution, the application injects the error-monitoring shim from:

```text
lib/sandbox.ts
```

The simulation is then rendered using a sandboxed iframe.

### Step 5 — Interact with the Simulation

The user can adjust the generated controls and observe the visualization.

The simulation runs inside the iframe, while the main application remains responsible for the surrounding interface and error handling.

### Step 6 — Repair Errors When Possible

If the iframe reports a runtime error, the parent component calls:

```text
/api/heal
```

The healing route sends the topic, previous code, and error details to Claude.

If a corrected document is returned, the iframe is remounted with the new HTML.

The process repeats until the simulation works or the maximum healing attempts are reached.

## Project Architecture

STEMly is organized into three main layers.

### 1. Frontend

The frontend is responsible for:

- Accepting the user's topic
- Displaying loading and error states
- Showing the generated simulation
- Detecting errors reported by the iframe
- Starting the automatic healing process

Main components:

- `SearchInterface`
- `TopicChips`
- `SimulationFrame`
- `LoadingState`
- `ErrorState`
- `HealingToast`

### 2. Backend

The backend contains two API routes.

**Generation API**

```text
app/api/generate/route.ts
```

This route receives a topic and calls the Anthropic API to generate a simulation.

**Healing API**

```text
app/api/heal/route.ts
```

This route receives a failed simulation and its error details, then asks Claude to return corrected HTML.

### 3. Shared Libraries

The `lib` directory contains shared logic and configuration.

- `prompts.ts` — generation and healing prompts
- `sandbox.ts` — error shim injection and response parsing
- `theme.ts` — shared palette and font tokens
- `types.ts` — shared TypeScript types

## Getting Started

### Prerequisites

Before running STEMly locally, make sure you have:

- Node.js 20 or later
- npm
- Git
- An Anthropic account
- An Anthropic API key

Check your installed versions:

```bash
node -v
npm -v
```

### 1. Clone the Repository

Replace the placeholder URL with your repository URL.

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
```

Move into the project directory:

```bash
cd YOUR_REPOSITORY
```

### 2. Install Dependencies

```bash
npm install
```

This installs the dependencies defined in `package.json`.

### 3. Configure Environment Variables

Copy the example environment file:

```bash
cp .env.example .env.local
```

On Windows Command Prompt, you can use:

```cmd
copy .env.example .env.local
```

Open `.env.local` and add your Anthropic API key:

```env
ANTHROPIC_API_KEY=your_anthropic_api_key
```

Do not commit `.env.local` or expose your API key in frontend code.

### 4. Start the Development Server

```bash
npm run dev
```

Open the application in your browser:

```text
http://localhost:3000
```

You can now enter a STEM topic and test the simulation generation workflow.

## API Routes

### `POST /api/generate`

Generates a new simulation from a STEM topic.

**Purpose**

Receives the user's topic, calls Claude, and returns the generated HTML document.

**Expected input**

The request contains the topic entered by the user.

Example request:

```json
{
  "topic": "Wave interference"
}
```

**Expected behavior**

1. Validate the request.
2. Read the topic.
3. Build the generation prompt.
4. Call the Anthropic Messages API.
5. Process the model response.
6. Return the generated simulation HTML.

The exact request and response schema is determined by the implementation in `app/api/generate/route.ts`.

### `POST /api/heal`

Attempts to repair a failed simulation.

**Purpose**

Uses the previous generated HTML and runtime error details to ask Claude for a corrected document.

The healing request includes:

- Topic
- Previous simulation code
- Runtime error information

**Expected behavior**

1. Receive the failed simulation details.
2. Build the repair prompt.
3. Ask Claude to correct the code.
4. Process the returned HTML.
5. Return the corrected simulation to the frontend.

The exact request and response schema is determined by the implementation in `app/api/heal/route.ts`.

## Simulation Generation and Healing

### Generation Prompt

The generation prompt is defined in:

```text
lib/prompts.ts
```

It instructs Claude to produce one self-contained HTML document.

The document is expected to include:

- HTML markup
- Inline CSS
- Inline JavaScript
- Interactive controls
- A Canvas or SVG visualization
- A STEMly-compatible visual style

The prompt also defines which external simulation libraries may be used.

### Sandbox Error Monitoring

The sandbox helper is defined in:

```text
lib/sandbox.ts
```

It injects an error-monitoring shim into the generated document.

The shim listens for common JavaScript runtime failures and sends error information to the parent window using `postMessage`.

The parent application can then decide whether to begin the healing process.

### Healing Loop

The healing loop is managed by:

```text
components/SimulationFrame.tsx
```

The current maximum number of healing attempts is:

```text
MAX_HEAL_ATTEMPTS = 3
```

The process is:

```text
Generate Simulation
        |
        v
Render in Sandboxed Iframe
        |
        v
Did a runtime error occur?
        |
   +----+----+
   |         |
  No        Yes
   |         |
   v         v
Ready     Send error to /api/heal
             |
             v
      Receive corrected HTML
             |
             v
       Remount the iframe
             |
             v
      Check the new simulation
```

If the simulation continues to fail after the allowed attempts, STEMly displays an error state instead of continuing indefinitely.

## Customization

### 1. Change the AI Model

The model is configured in the generation and healing API routes:

```text
app/api/generate/route.ts
app/api/heal/route.ts
```

The current project configuration uses:

```text
claude-sonnet-5
```

Update the model identifier in both routes if you decide to use another model supported by your Anthropic account.

Always verify that the selected model identifier is currently available.

### 2. Change the Theme

The shared theme is defined in:

```text
lib/theme.ts
```

The main application's design tokens are defined in:

```text
app/globals.css
```

When changing the palette or fonts, update the relevant shared values and ensure the generation prompt continues to describe the intended simulation style.

### 3. Change the Number of Healing Attempts

The healing attempt limit is configured in:

```text
components/SimulationFrame.tsx
```

Look for:

```text
MAX_HEAL_ATTEMPTS
```

Increasing the limit may improve the chance of recovering from some errors, but it can also increase response time and API usage.

### 4. Change Allowed Simulation Libraries

The generation prompt lists the external libraries Claude is permitted to use.

The current allowed library examples include:

- Three.js
- p5.js
- D3
- Math.js
- Chart.js

The exact CDN script tags and restrictions are defined in:

```text
lib/prompts.ts
```

Only allow libraries that are necessary and that you are comfortable permitting inside generated simulations.

## Deployment on Vercel

STEMly can be deployed to Vercel as a Next.js application.

### Step 1 — Push the Project to GitHub

Create a repository and push the project:

```bash
git add .
git commit -m "Prepare STEMly for deployment"
git push origin main
```

Make sure secret files such as `.env.local` are excluded from version control.

### Step 2 — Import the Repository

1. Open Vercel.
2. Select **Add New → Project**.
3. Import your GitHub repository.
4. Allow Vercel to detect the Next.js framework.
5. Review the project settings.

### Step 3 — Add the API Key

In Vercel:

1. Open **Project Settings**.
2. Select **Environment Variables**.
3. Add `ANTHROPIC_API_KEY`.
4. Paste your Anthropic API key as the value.
5. Select the environments where it should be available.

Do not add the API key to client-side code.

### Step 4 — Deploy

Start the deployment.

After deployment completes, open the provided URL and test:

- Topic submission
- Simulation generation
- Iframe rendering
- Interactive controls
- Runtime error reporting
- Healing behavior

### Function Duration

Both API routes configure:

```text
maxDuration = 60
```

This allows the routes to request a longer execution window where the hosting plan supports it.

Serverless function duration limits depend on the current Vercel plan and configuration. Check the current plan limits if generation requests time out.

If needed, consider reducing the model's output length or simplifying the generation prompt.

## Troubleshooting

### The API Key Is Missing

**Possible cause:** `ANTHROPIC_API_KEY` is not configured.

**Check:**

- `.env.local` exists.
- The variable name is spelled correctly.
- The development server was restarted after changing the environment file.
- The key is configured in Vercel for the relevant deployment environment.

### Simulation Generation Fails

**Possible causes:**

- Invalid or missing API key
- API request failure
- Model identifier unavailable
- Rate limit or usage limit
- Invalid model response
- Request timeout

Check the terminal or deployment logs for details.

### The Simulation Is Blank

**Possible causes:**

- Generated HTML is malformed.
- The simulation contains a JavaScript error.
- The generated code relies on a blocked external resource.
- The visualization does not initialize correctly.

Check the browser console and confirm that the iframe is receiving the expected HTML.

### Automatic Healing Does Not Work

**Possible causes:**

- The iframe error message is not reaching the parent.
- The healing API request fails.
- The healing response does not contain valid HTML.
- The maximum healing attempt limit has been reached.

Review the message handling in `SimulationFrame.tsx` and the error shim in `lib/sandbox.ts`.

### Deployment Times Out

**Possible causes:**

- The model response takes longer than the configured function duration.
- The generated output is too large.
- The deployment plan has a lower execution limit.

Review the current Vercel function duration limits and consider simplifying the prompt or reducing the maximum output length.

## Limitations

STEMly is an experimental AI-powered learning tool. Generated simulations may contain mistakes or incomplete explanations.

Keep the following limitations in mind:

- AI-generated scientific explanations may be inaccurate.
- Some topics may be too complex for a single generated simulation.
- The visual model may simplify real-world behavior.
- A simulation can contain logical errors even if it runs without crashing.
- Automatic healing focuses on runtime errors and does not guarantee scientific correctness.
- External libraries may fail to load or may be unavailable.
- Generated content should not replace textbooks, laboratory procedures, or expert guidance.

For educational use, compare important results with trusted course materials or scientific references.
